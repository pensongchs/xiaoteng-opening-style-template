# 运行与复刻

## 安装 Skill

将本仓库的 `skills/xiaoteng-opening-style-template/` 安装为一个技能目录。用户可直接把仓库链接交给 Codex，要求安装这个目录。安装完成后新开对话，使用 `$xiaoteng-opening-style-template` 或“小滕片头风格模板”。

技能指令的安装与视频工程的运行是两件事。首次使用应创建工作副本并跑通下述完整示例。

## 创建工作母工程

由 Codex 推导当前技能目录和学员选择的工作目录，执行：

```text
node "技能安装目录/scripts/create-project.mjs" "学员工作目录/outputs/片头制作专用"
```

目标已存在时脚本拒绝覆盖。让 Codex检查并续接已有工程，不要换个名字反复创建同类工程。路径有中文或空格时使用完整引号；Windows也使用Node脚本，避免手工拼接shell命令。

## 双系统准备

在工作工程内运行 `node scripts/setup.cjs`。首次可能下载数百MB至约1GB的依赖和浏览器，实际大小随系统和缓存变化；之后同环境复用缓存。安装不会改变系统字体或系统权限设置。

| 系统 | 自动判断与处理 |
| --- | --- |
| Apple芯片Mac | 使用arm64的Node与Mac浏览器/编码器；macOS 15以上 |
| Intel Mac | 使用x64的Node与Mac浏览器/编码器；macOS 15以上 |
| Windows 10/11 x64 | 使用x64的Node、浏览器和编码器；依赖通过junction连接，不需要管理员符号链接权限 |
| Windows 11 ARM | 识别并提示使用x64 Node的兼容环境；当前不支持原生ARM Node渲染，ARM兼容模式需要在实际电脑验证 |

桌面默认使用ANGLE渲染；检测到CI云端环境时自动使用适用于无显卡机器的swangle兼容渲染并将并发降为1，分辨率、帧率和背景着色器保持一致。

Node最低22，建议24 LTS。没有Node或版本过低时，Mac运行`start.command`，Windows运行`start.cmd`会显示系统与匹配的官方安装入口；Codex可以据此完成当前授权范围内的安装。不要让学员修改代码里的用户名或路径。

共享目录为`CODEX_HOME/shared-node-dependencies/`；未设置`CODEX_HOME`时为用户主目录下`.codex/shared-node-dependencies/`。运行组按完整依赖清单、锁文件、npm、Node主版本、系统与架构生成指纹；npm包、浏览器和官方背景缓存可复用。依赖版本变化建立新组，不覆盖其他工程。

## 验收示例

```text
npm run setup
npm run check
npm test
npm run render
npm run verify
npm run still -- 103 "预览图/示例中段.png"
```

应生成`renders/示例片头.mp4`：1920×1080、50fps、184帧、3.68秒、H.264、无音轨。类型检查、媒体解码、黑帧检查和关键画面通过，才算这台电脑可以运行。`npm run doctor`只证明环境检查通过。

示例使用随包透明住宅和三款字体；背景从React Bits固定提交获取，下载校验失败会停止，不静默改成静态图或近似效果。首次需能访问npm、GitHub原始文件和Remotion浏览器下载源。

## 常见问题

- Node缺失、旧版本或Windows使用ARM Node：按启动器报告安装对应Node，重新打开终端后再跑setup。
- 背景下载失败：检查网络，保留错误来源URL，恢复后重跑setup；已校验资源会复用。
- 共享运行组不完整：让Codex核对指纹与本机编码器，修复对应运行组；不要直接在共享node_modules中npm install。
- Mac渲染出现`SIGTRAP`或沙箱权限拒绝：区分操作系统权限与素材/代码错误，按当前工具权限重试同一命令，不通过关闭系统防护解决。
- 中文路径和空格：脚本使用Node路径API及参数数组；不要改成未经转义的shell拼接。
- 只改配置却仍显示示例文案：本期布局还可能在Opening.tsx中有固定短语、年份与坐标，让Codex检查实际渲染引用。
